║                          EXECUTION & DATA FLOW                               ║
╚══════════════════════════════════════════════════════════════════════════════╝

1. SEARCH FLOW:
═══════════════
 User Input (CLI / TUI / GUI)
    ↓
 [GoProviderEngine.search(query)]
    ↓
 Go Engine runs concurrent goroutines for each active provider:
    ├─→ [Repository] (pacman/apt/dnf/zypper)
    ├─→ [AUR] (aur.archlinux.org RPC API v5)
    ├─→ [Flatpak] (flathub)
    ├─→ [Snap] (snapcraft)
    └─→ [GitHub] (github releases API)
    ↓
 Aggregate & deduplicate in memory, save to `~/.cache/arjax/provider_cache.json`
    ↓
 Stream formatted results to GUI / TUI / CLI in < 300ms.


2. INSTALLATION FLOW:
═════════════════════
 User clicks "Install" / `arjax install <pkg>`
    ↓
 Evaluate Recipe / Provider Priority Chain:
    Repository (Pacman/APT/DNF/Zypper) → AUR (if Arch) → Vendor → Flatpak → Snap → GitHub
    ↓
 Step-based execution with live progress output:
    1. Resolve dependencies
    2. Download binary/source or build PKGBUILD
    3. Run installer with sudo elevation where needed
    4. Link binaries to `~/.local/bin/`
    ↓
 Track package installation state in `~/.arjax/installed.json`
    ↓
 Display live status updates in GUI and TUI.


3. GRACEFUL FALLBACK (NO GO COMPILER):
══════════════════════════════════════
 If user environment does not have Go or `arjax-provider` binary:
    • `GoProviderEngine.is_available()` returns `False`
    • GUI & CLI seamlessly fall back to Python search and installer modules
    • Zero crashes, zero external runtime hard dependencies required
